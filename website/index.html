A service manager for your own computer, with every service isolated.

Pythonator keeps your web applications, APIs, workers, databases and scheduled jobs running on Windows, macOS and Linux. A background service reconciles what is running with what you configured, and no service starts until you have reviewed and approved the access it is given.

01 · Supervision

Supervised by a background service.

pythonatord manages every service and continues to run when the window is closed. The window is a client only; closing it minimises Pythonator to the system tray.

Restarts, health checks, schedules

Restarts with back-off and a delayed retry after repeated failures. HTTP or TCP health checks. Cron schedules that run missed jobs after the computer was off. A service that cannot start is marked Blocked with the reason, instead of being restarted repeatedly.

Services

Kernel-enforced resource limits

Memory, CPU and task limits for the whole process tree: cgroups on Linux and in WSL, a job object on Windows, and the engine's limits in a container. Where a limit is weaker, the plan marks it reduced.

Isolation

Efficient, masked logs

Output is stored in indexed segments and read by range, with ANSI colours, so large logs do not slow the interface. Secrets, token formats and private keys are masked before they reach the disk, a plugin or a webhook.

Logs

Integrated editor

Each service's files, with syntax highlighting, completion from the project's modules and packages, a configurable linter, Git status and a snapshot on every approval. Try in a copy runs a change in a temporary folder first.

Snapshots

Desktop applications

A service can be a GUI application (PyQt, Tk, Electron) in Full access, or in Sandbox on Windows, where the job object prevents access to other windows and the clipboard.

GUI apps

Straightforward installation and removal

An installer for each operating system sets up the application and its login service for your user. pythonatorctl uninstall stops every service and revokes every folder permission.

02 · Isolation

Four isolation modes, strictly enforced.

If a protection cannot be enforced on this machine, the service is not started, and the reason and remedy are shown. Pythonator never runs a service with less protection than its plan states.

ModeAccessBuilt on
SandboxIts own folder and its runtime only. Your home folder, keys, browser data and other projects are not visible.bubblewrap, Landlock and seccomp on Linux, a Seatbelt profile on macOS, an AppContainer in a job object on Windows

03 · Plans

Explicit approval of every change

Each change produces a plan that lists the protections in effect on this machine and any access that would widen (a folder, a host, a port, a window on your screen). Approval is bound to a hash of those fields, so any later change that widens access requires approval again.

Outbound traffic is Off, limited to a list of hosts through Pythonator's egress gate, or unrestricted. Each blocked connection is listed and can be allowed with one click.

04 · Plugins

Isolated plugins

Each plugin runs in its own isolated environment with no network access and no access to your home folder. Plugins start with no permissions, and every grant is tied to a hash of the plugin's code, so any change to the code revokes its grants.

  • Guard: policy rules (modes, ports, memory) that every change must satisfy before it is applied
  • Notify: notifications of failures, blocks and recoveries to Discord, Slack, ntfy or a webhook
  • AI assistant: answers questions about a service's logs and code, and proposes changes for your review
  • Builder: creates new projects from templates, inside a sandbox
