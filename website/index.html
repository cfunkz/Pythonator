A service manager for your own computer, each service in a jail.

Pythonator keeps your web apps, APIs, workers, databases and scheduled jobs running on Windows, macOS and Linux. A background service makes what runs match what you asked for, and nothing runs until you have seen and approved what it may reach.

01 · Supervision

Kept running, by a background service.

pythonatord owns every service and keeps running when the window closes. The window is only a client; closing it hides it to the tray.

Restarts, health checks, schedules

Restarts with back-off and a cool-down retry after giving up. HTTP or TCP health checks. Cron schedules that catch up after the computer was off. A service that can never start stays Blocked with the reason, instead of looping.

Services

Limits from the kernel

Memory, CPU and tasks for the whole process tree: cgroups on Linux and in WSL, a job object on Windows, the engine's limits in a container. Where a limit is weaker, the plan says reduced.

Isolation

Logs that can't freeze the window

Output is stored in indexed segments and read by range, with ANSI colours. Secrets, token formats and private keys are masked before anything reaches the disk, a plugin or a webhook.

Logs

An editor beside it

Each service's files, with highlighting, a linter you can turn down, Git status and snapshots taken on every approval. Try in a copy runs a change in a throwaway folder first.

Snapshots

Desktop apps too

A service can be a GUI app (PyQt, Tk, Electron) in Full access, or in Sandbox on Windows, where the job keeps other windows and the clipboard out of reach.

GUI apps

Easy to install and to remove

An installer for each OS sets up the app and its login service, as you. pythonatorctl uninstall stops everything and takes back every folder permission.

02 · Isolation

Four modes. Refused, never "cooperative".

If a layer can't be enforced on this machine, the start is refused with a code and the fix. Pythonator never runs a service with less protection than its plan shows.

ModeWhat it can reachBuilt on
SandboxIts own folder and its runtime. Not your home, keys, browser data or other projects.bubblewrap, Landlock and seccomp on Linux, a Seatbelt profile on macOS, an AppContainer in a job object on Windows

03 · Plans

You approve a plan, not a checkbox

Each change produces a plan: which layers protect the service on this machine, and what would widen (a folder, a host, a port, a window on your screen). Your approval is bound to a hash of those fields, so nothing that widens access slips in later without asking again.

Traffic out is Off, a list of hosts through Pythonator's egress gate, or Anywhere. Each blocked connection is listed, with one click to allow it.

04 · Plugins

Plugins that can't hurt you

Each plugin runs in its own jail with no network and no home, starts with no permissions, and its grants are tied to a hash of its code. Change the code and the grants are gone.

  • Guard: rules a change must pass (modes, ports, memory) before it is applied
  • Notify: crashes, blocks and recoveries, sent to Discord, Slack, ntfy or a webhook
  • AI assistant: questions about a service's logs and code, with changes you review first
  • Builder: new projects from templates, made in a sandbox
