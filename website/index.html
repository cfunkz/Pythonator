Keep your bots and servers running, each in its own sandbox.

Pythonator starts the programs that should not stop, restarts them when they fail, and keeps each one to its own folder and the ports you list. It has a fast code editor built in, and plugins add the rest. One small desktop app, the same on Windows, macOS and Linux.

Download Getting started

From source with Python 3.12 or later: pip install -e . and run pythonator. No Docker, WSL or administrator rights needed.

01 · Supervision

Start it once. It keeps running.

A service is a file to run or a command. Pythonator runs it in a background service that keeps going after you close the window, and decides after every exit whether to start it again.

Restarts that back off

On failure or always, waiting 1 s, 2 s, 4 s and up to a minute. Too many restarts in ten minutes and it stops trying and tells you, instead of looping forever.

Restarts

Schedules and limits

every 15m, @daily or any cron line. A memory limit for the whole process tree: a kernel limit on Windows and in containers, a watchdog elsewhere.

Schedules

A console that keeps up

Colours, input, and hundreds of thousands of lines without freezing the window. Tokens and passwords from the environment are masked before anything is shown or written to the log.

Console and logs

Code from Git

Clone a repository as a service and pull before a start. Fast-forward only, hooks off, and only https and ssh addresses.

Git

An editor beside it

QScintilla, the engine behind Notepad++: highlighting for every language here, folding, multiple carets, find and replace, and big files that open instantly.

Shortcuts

Packages stay with the project

Install packages makes a .venv for Python, node_modules for Node and Bun, vendor for PHP and Ruby, inside the service's own isolation. Nothing goes into your account.

02 · Isolation

Three modes. Sandbox is the default.

Every operating system has containment built in. Pythonator puts a simple switch on it. If a protection can't be applied, the service doesn't start: it never quietly runs with less.

ModeWhat it can reachBuilt on
SandboxIts own folder, its language, and the ports you list. Not your home folder, keys, other projects or Pythonator's data.Landlock, seccomp and bubblewrap on Linux, Seatbelt on macOS, AppContainer on Windows
ContainerOnly the project folder, mounted at /app. Can join a container network to reach a database.Docker or Podman with every capability dropped, a read-only image and no new privileges
Full accessEverything your account can. Asks you once, and shows in red.A normal process, still in a job or process group so stopping ends all of it

03 · Ports and APIs

Reachable when you say so, and only there

List the ports a service serves. In Sandbox mode it may listen on those and no others. Choose This computer for an API only your own programs call, or Other computers too for a server on your network. Windows needs one administrator prompt for it, which Make reachable does for you, and Undo takes back.

04 · Plugins

Official plugins are verified. Others are contained.

Plugins run in processes of their own, in the same sandbox as services, and talk to Pythonator only through a small message protocol. An official plugin is one whose files match a SHA-256 catalog reviewed with every change. Any other plugin starts in test mode with nothing granted: what it tries is only recorded until you grant permissions.

  • Notify: one timeline of crashes, blocked starts, recoveries, failing health checks and anomalies, sent to Discord, Slack, Telegram, Teams, ntfy or any URL
  • Guard: rules for modes and ports before a start, and a watchdog for memory and CPU
  • Project builder: React, Vue, Nuxt, FastAPI, Flask or Django in one click, by each framework's own tool, in a sandbox

05 · Install

From a release or from source

Source installs need Python 3.12 or later. Dependencies are few, pinned with hashes in requirements.lock, and audited for known vulnerabilities on every change.
