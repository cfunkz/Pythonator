# Security cases: how 0.0.1 answers each one

Every item of the 286-case checklist from the audits and fix rounds of the old app (0.0.1 to 0.0.19), answered for
this release. Each answer is one of:

- **Removed by construction**: the feature or path that caused it doesn't exist here.
- **Handled in code**: where it is handled, and the test that fails CI if it regresses.
- **Open**: not done in 0.0.1, with the reason. Open items are also listed first, below.

**Totals:** 73 removed by construction · 201 handled in code · 12 open · 286 in all.

Paths are under `pythonator/` unless they start with `tests/`, `docs/` or `.github/`. Test names are in
`tests/`; the 16 invariant tests are `tests/test_invariants.py::test_<n>_*`.

## Open items

| # | Why it is open |
| --- | --- |

| 1.1.17 | Same as the previous item on Windows. On POSIX the specs are under the 0700 data folder, so no other account can change them. |

| 1.6.18 | No Node preload or `--preserve-symlinks`; unverified like the two items above. |

## 2. Bugs that kept coming back: the design answer

| # | Class | Answer in 0.0.1 |
| --- | --- | --- |
| 1 | The daemon trusted files in a folder the service can write. | One safe reader (`safe/safefs.py`) for every read of a service folder, enforced by a lint test (`test_1_only_safefs_reads_service_folders`); no runtime, git or engine is ever run as you inside a service folder; git metadata lives in the data folder. |
| 2 | Environment variables crossing the boundary. | Host tools get an environment built from an allow-list (`safe/hostenv.host_env`); the service environment is a separate value that only reaches the jailed child (`test_2_*`). |
| 3 | Git pull as you inside a sandbox's folder. | No pull or clone. Private snapshots in a per-service git dir in the data folder (`work/git.py`, `test_3_*`). |
| 4 | Processes escaping Stop. | A kernel container per run: bubblewrap PID namespace or a systemd scope (Linux), a job object (Windows), the container, WSL's cgroup; markers only on macOS (`test_4_*`). |
| 5 | User-space limits. | Kernel limits first (cgroup, job, container flags), with "reduced" where only the watchdog applies; the watchdog uses private bytes (`test_4_5_every_plan_has_a_tree_and_limits_row`). |
| 6 | Windows ACL grants damaging the user's system. | Grant ledger with intend/done rows, a named mutex, repair at start, revoke on diff and on uninstall (`reconciler._revoke_grants`, `jail/winjail.py`, `test_16_*`). |
| 7 | Blocking the daemon or GUI thread. | asyncio everywhere in the daemon, subprocesses with timeouts, bounded queues (IPC 8 MB, plugin 2 MB, stdin 64 KB); the window never blocks on the daemon. No flood/latency CI test yet; numbers in the daily measure. |
| 8 | Fail-open fallbacks and detection that didn't match reality. | Detection is a real start (System check runs a jail); each missing layer is a tested refusal (`test_8_missing_layer_refuses`). |
| 9 | Half fixes and fixes bypassed by a neighbour. | Class-level tests for each finding: any link, any special file, any trailing newline, any host-side variable (`tests/test_hardening.py`). |
| 10 | Bare program names and PATH lookup. | One resolver (`safe/hostenv.resolve`) plus a lint that bans bare names (`test_10_*`). |
| 11 | Secret masking by name. | Value masking at one choke point for every channel, plus token shapes and private keys (`safe/mask.py`, `test_11_*`). |
| 12 | Docs and claims drifting from the code. | docs/isolation.md tables generated from the compiler (`python -m pythonator.service.check --doc`, `test_12_*`). |
| 13 | Windows pipe squatting. | No pipe: challenge-response over a 0700 Unix socket or loopback TCP; the key never crosses (`test_ping_and_wrong_key_is_refused[tcp]`). Windows CI job runs the tcp path. |
| 14 | Uncaught Qt exceptions killing everything | Global excepthook from start (`safe/process.install_hook`, `test_14_*`). |
